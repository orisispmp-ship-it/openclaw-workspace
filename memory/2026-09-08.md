## 텔레그램 발신 장애 (IPv6) 발견·수리

- 증상: 크론 announce 전송 "Network request for 'sendMessage' failed!" + conversations_send 타임아웃. getUpdates 폴링은 되는 듯 보임.
- 원인 확정: **Wi-Fi에 글로벌 IPv6 부재** (ULA fd50:...만 존재, ::/0 기본 경로 없음). api.telegram.org가 AAAA 반환 → node/undici가 IPv6 먼저 시도 → ETIMEDOUT, IPv4 폴백 안 함. curl은 IPv4라 정상.
- 검증: `node -e fetch(api.telegram.org)` 실패 / `--dns-result-order=ipv4first`도 무효 / IPv4 리터럴+SNI로는 302 성공.
- **조치: `Disable-NetAdapterBinding -Name "Wi-Fi" -ComponentID ms_tcpip6`** (유이사님 승인) → node fetch 200 OK. 게이트웨이 재시작 후 유이사님 텔레그램 수신 확인 ("잘와").
- hosts 파일 고정은 보안 SW가 SYSTEM도 차단(액세스 거부) → 사용 안 함.
- 되돌리려면: `Enable-NetAdapterBinding -Name "Wi-Fi" -ComponentID ms_tcpip6`
